---
title: Dependency Resolution Strategies
description: Understanding how rebaze resolves external dependencies
---

Rebaze supports multiple strategies for resolving external dependencies. Choose based on your needs for hermeticity, build speed, and environment.

## Available Strategies

| Strategy | Hermetic | Speed | Setup |
|----------|----------|-------|-------|
| `system` | No | Fast | Minimal |
| `source` | Yes | Slow (first build) | Moderate |
| `vcpkg` | Partial | Moderate | vcpkg install |
| `conan` | Partial | Moderate | Conan install |

## System Strategy (Default)

Uses system-installed libraries via pkg-config.

```toml
[strategy]
default = "system"
```

**How it works:**
1. Rebaze generates `cc_library` targets with `linkopts`
2. At build time, pkg-config resolves library paths
3. System libraries are linked

**Pros:**
- Fast builds (no compilation of deps)
- Simple setup
- Works with existing system packages

**Cons:**
- Non-hermetic (different machines may have different versions)
- Requires libraries installed on build machine
- Not reproducible across environments

**Generated code:**

```python
# third_party/BUILD.bazel
cc_library(
    name = "zlib",
    linkopts = ["-lz"],
)
```

## Source Strategy

Builds dependencies from source using `rules_foreign_cc`.

```toml
[strategy]
default = "source"
```

**How it works:**
1. Rebaze downloads source archives
2. `rules_foreign_cc` builds them (cmake, autotools, meson)
3. Built libraries are used as deps

**Pros:**
- Fully hermetic
- Reproducible builds
- Same version everywhere

**Cons:**
- Slower first build
- Requires package metadata in config
- More complex setup

**Generated code:**

```python
# third_party/source.bzl
cmake(
    name = "zlib",
    lib_source = "@zlib//:all_srcs",
    out_static_libs = ["libz.a"],
)
```

## Per-Package Overrides

Mix strategies based on your needs:

```toml
[strategy]
default = "system"

[strategy.overrides]
# Build these from source for hermeticity
openssl = "source"
zlib = "source"

# Use system for large/complex deps
qt = "system"
```

## Choosing a Strategy

### Use `system` when:

- Developing locally
- Dependencies are stable system packages
- Build speed is important
- CI has consistent environment

### Use `source` when:

- Reproducibility is critical
- Building in varied environments
- Pinning exact dependency versions
- Creating release builds

### Hybrid approach:

Most projects benefit from a hybrid:

```toml
[strategy]
default = "system"  # Fast local development

[strategy.overrides]
# Pin critical deps for release builds
openssl = "source"
```

## Strategy Resolution

When rebaze generates dependency targets, it:

1. Checks `strategy.overrides` for the specific package
2. Falls back to `strategy.default`
3. Generates appropriate BUILD rules

The generated `third_party/config.bzl` allows runtime strategy selection:

```python
# third_party/config.bzl
STRATEGY = {
    "default": "system",
    "zlib": "source",
    "openssl": "source",
}
```

## CI Considerations

For CI pipelines:

```toml
# rebaze.toml for CI
[strategy]
default = "source"  # Hermetic builds
```

Or use environment-specific configs:

```bash
# Local development
rebaze migrate . --config rebaze.local.toml

# CI builds
rebaze migrate . --config rebaze.ci.toml
```
