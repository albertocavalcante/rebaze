This page describes all files that rebaze generates during migration.

## Core Files

These files are generated for all projects.

### MODULE.bazel

The Bazel module definition file. Declares the module name, version, and dependencies.

```python
module(
    name = "myproject",
    version = "0.1.0",
)

bazel_dep(name = "rules_cc", version = "0.1.1")
bazel_dep(name = "platforms", version = "0.0.11")
bazel_dep(name = "googletest", version = "1.15.2")
```

### BUILD.bazel

The root build file containing target definitions.

```python
load("@rules_cc//cc:defs.bzl", "cc_binary", "cc_library")

cc_library(
    name = "mylib",
    srcs = ["src/lib.cpp"],
    hdrs = ["include/mylib.h"],
    includes = ["include"],
    visibility = ["//visibility:public"],
)

cc_binary(
    name = "myapp",
    srcs = ["src/main.cpp"],
    deps = [":mylib"],
)
```

### .bazelversion

Pins the Bazel version for reproducibility.

```
9.0.0
```

### .bazelrc

Build configuration with sensible defaults.

```bash
# C++ settings
build --cxxopt=-std=c++17
build --host_cxxopt=-std=c++17

# Enable position-independent code
build --copt=-fPIC

# Warning settings
build --copt=-Wall
build --copt=-Wextra

# Test settings
test --test_output=errors

# CI config
build:ci --color=yes
build:ci --curses=no
```

## Third-Party Files

Generated when the project uses pkg-config dependencies.

### third_party/BUILD.bazel

Alias targets that resolve based on the configured strategy.

```python
load(":config.bzl", "STRATEGY")
load(":system_deps.bzl", "system_library")
load(":source.bzl", "source_library")

alias(
    name = "zlib",
    actual = select({
        ":use_system": ":zlib_system",
        ":use_source": ":zlib_source",
    }),
    visibility = ["//visibility:public"],
)

system_library(
    name = "zlib_system",
    pkg_config = "zlib",
)

source_library(
    name = "zlib_source",
    # Defined in source.bzl
)
```

### third_party/config.bzl

Central configuration for dependency resolution.

```python
# Dependency resolution strategy
# Options: "system", "source", "vcpkg", "conan"
STRATEGY = {
    "default": "system",
    "zlib": "source",
    "openssl": "source",
}

def get_strategy(name):
    return STRATEGY.get(name, STRATEGY["default"])
```

### third_party/source.bzl

Module extension for building dependencies from source.

```python
load("@rules_foreign_cc//foreign_cc:defs.bzl", "cmake")

def _source_deps_impl(ctx):
    cmake(
        name = "zlib",
        lib_source = "@zlib//:all_srcs",
        out_static_libs = ["libz.a"],
    )

source_deps = module_extension(
    implementation = _source_deps_impl,
)
```

### third_party/system_deps.bzl

Macro for wrapping system libraries.

```python
def system_library(name, pkg_config, **kwargs):
    """Wrapper for system libraries using pkg-config."""
    native.cc_library(
        name = name,
        linkopts = ["-l" + pkg_config],
        **kwargs
    )
```

## File Structure

After migration, your project structure looks like:

```
myproject/
├── MODULE.bazel          # Module definition
├── BUILD.bazel           # Root targets
├── .bazelversion         # Bazel version
├── .bazelrc              # Build config
├── third_party/          # (if using pkg-config deps)
│   ├── BUILD.bazel
│   ├── config.bzl
│   ├── source.bzl
│   └── system_deps.bzl
├── src/                  # Your source files
│   └── ...
└── include/              # Your headers
    └── ...
```

## Customizing Generated Files

After migration, you can customize:

1. **MODULE.bazel** - Add more dependencies, change versions
2. **BUILD.bazel** - Add targets, modify visibility
3. **third_party/config.bzl** - Change strategies per-package
4. **.bazelrc** - Add custom build configurations

Rebaze doesn't overwrite existing files by default, so your customizations are preserved on re-runs.
