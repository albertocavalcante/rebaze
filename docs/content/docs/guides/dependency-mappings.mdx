---
title: Configure Dependency Mappings
description: How to map CMake dependencies to Bazel targets
---

When migrating from CMake, rebaze needs to know how to translate CMake dependencies to Bazel targets. This guide covers all mapping types.

## Types of Dependencies

CMake projects reference dependencies in several ways:

| CMake Pattern | Example | Mapping Section |
|---------------|---------|-----------------|
| `-l` flag | `-lz`, `-lssl` | `system_libraries` |
| Plain name | `gtest`, `boost` | `plain_libraries` |
| Package::Component | `OpenSSL::SSL` | `packages` |
| Implicit | `pthread`, `m` | `implicit_system_libs` |

## System Libraries

Map `-l` flags to Bazel targets:

```toml
[mappings.system_libraries]
z = "@zlib"
zlib = "@zlib"
ssl = "@openssl//:ssl"
crypto = "@openssl//:crypto"
curl = "@curl"
```

## Plain Libraries

Map plain library names (without `-l` or `::`):

```toml
[mappings.plain_libraries]
gtest = "@googletest//:gtest"
gtest_main = "@googletest//:gtest_main"
gmock = "@googletest//:gmock"
benchmark = "@google_benchmark//:benchmark"
```

## CMake Packages

Map `find_package()` targets using patterns:

```toml
[mappings.packages.Boost]
target_pattern = "@boost//:{component}"

# Component overrides
[mappings.packages.Boost.components]
filesystem = "@boost//:filesystem"
system = "@boost//:system"
```

The `{component}` placeholder is replaced with the actual component name.

### Example: OpenSSL

```toml
[mappings.packages.OpenSSL]
target_pattern = "@openssl//:{component}"

[mappings.packages.OpenSSL.components]
SSL = "@openssl//:ssl"
Crypto = "@openssl//:crypto"
```

Maps:
- `OpenSSL::SSL` → `@openssl//:ssl`
- `OpenSSL::Crypto` → `@openssl//:crypto`

### Example: Protobuf

```toml
[mappings.packages.Protobuf]
target_pattern = "@com_google_protobuf//:{component}"

[mappings.packages.Protobuf.components]
protobuf = "@com_google_protobuf//:protobuf"
protobuf_lite = "@com_google_protobuf//:protobuf_lite"
protoc = "@com_google_protobuf//:protoc"
```

## Implicit System Libraries

Libraries provided by the system that don't need Bazel targets:

```toml
[mappings]
implicit_system_libs = [
    "pthread",  # POSIX threads
    "c",        # C standard library
    "m",        # Math library
    "dl",       # Dynamic linking
    "rt",       # Real-time extensions
]
```

These are silently ignored during migration.

## Ignored Libraries

Libraries to skip completely (often bundled or header-only):

```toml
[mappings]
ignored_libraries = [
    "fmt",              # Often bundled
    "spdlog",           # Often bundled
    "Threads::Threads", # Handled by toolchain
]
```

## Transitive Dependencies

Define dependencies that should be pulled in transitively:

```toml
[mappings.transitive_deps]
glib = ["pcre2", "libffi", "zlib"]
gobject = ["glib", "libffi"]
curl = ["zlib", "openssl"]
```

When `glib` is used, `pcre2`, `libffi`, and `zlib` are also added.

## System Linkopts

Fallback linker flags when pkg-config isn't available:

```toml
[mappings.system_linkopts]
"glib-2.0" = ["-lglib-2.0"]
"gobject-2.0" = ["-lgobject-2.0"]
curl = ["-lcurl"]
openssl = ["-lssl", "-lcrypto"]
```

## Priority Order

When resolving a dependency, rebaze checks in this order:

1. `ignored_libraries` - Skip if listed
2. `implicit_system_libs` - Skip if listed
3. `-l` prefix → `system_libraries`
4. `::` separator → `packages`
5. Plain name → `plain_libraries`
6. Default → Warning, dependency skipped

## Debugging Mappings

Use `--dry-run` to see how dependencies are resolved:

```bash
rebaze migrate . --dry-run 2>&1 | grep -i "mapping\|unknown"
```

Warnings indicate unmapped dependencies that need configuration.
