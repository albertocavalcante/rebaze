Build rebaze from the repository, then verify the CLI before migrating a project.
The source paths below follow the repository's Cargo and Bazel configuration.

## Requirements

- Git and a native C/C++ toolchain for linking.
- For Bazel builds: Bazelisk, or the version recorded in `.bazelversion`.
  Bazel provisions the configured Rust toolchain.
- For Cargo builds: rustup and the toolchain in `rust-toolchain.toml`.
- For normal migration validation: Bazel 9 and the input project's build dependencies.
  CMake migration also configures/builds the original project with CMake.

## Build with Bazel

```bash
git clone https://github.com/albertocavalcante/rebaze.git
cd rebaze
bazel build //crates/rebaze-cli:rebaze
bazel run //crates/rebaze-cli:rebaze -- --help
```

The binary is `bazel-bin/crates/rebaze-cli/rebaze` (`rebaze.exe` on Windows).
You can run it by that path, use `bazel run` from the checkout, or copy it to a
user-owned directory on `PATH`.

On macOS/Linux, install the built binary for your user account:

```bash
install -d "$HOME/.local/bin"
install -m 755 bazel-bin/crates/rebaze-cli/rebaze "$HOME/.local/bin/rebaze"
export PATH="$HOME/.local/bin:$PATH"
rebaze --version
```

The export affects the current shell. Add that PATH entry to your shell's
configuration if you want it in future sessions.

## Build with Cargo

From the rebaze checkout:

```bash
rustup toolchain install --no-self-update
cargo build --release --locked -p rebaze-cli
cargo run --release --locked -p rebaze-cli -- --help
```

The release binary is `target/release/rebaze` (`rebaze.exe` on Windows). To install
through Cargo into its user bin directory instead:

```bash
cargo install --locked --path crates/rebaze-cli
rebaze --version
```

Ensure your Cargo bin directory is on `PATH`. On Windows, you can also run either
built `.exe` by its full path without changing the system PATH.
