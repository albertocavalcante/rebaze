## Quick reference

```bash
rebaze analyze [PATH]              # Detect build system
rebaze migrate [PATH] [OPTIONS]    # Generate Bazel files
rebaze validate [PATH]             # Verify migration
```

## Global options

| Option | Description |
|--------|-------------|
| `-v, --verbose` | Enable verbose output |
| `--version` | Print version |
| `-h, --help` | Print help |

---

## `rebaze analyze`

Detect the build system of a project.

```bash
rebaze analyze /path/to/project
```

**Output:**
```
Detected build systems: cmake, gradle
```

| Argument | Default | Description |
|----------|---------|-------------|
| `PATH` | `.` | Project root |

**Detectable systems:** cmake, gradle, maven, make, cargo

## `rebaze migrate`

Generate Bazel build files from your existing build system.

```bash
rebaze migrate /path/to/project
```

### Basic options

| Option | Description |
|--------|-------------|
| `--dry-run` | Preview without writing files |
| `-f, --from <SYSTEM>` | Force build system (auto-detected) |
| `-c, --config <FILE>` | Path to rebaze.toml |
| `--unsafe-mode` | Skip pre/post build checks; input/configuration/generation checks still apply |

Preview reads project inputs and may run bounded pkg-config discovery. It runs no
builds, executes no Bazelle version probe, and writes no generated files. Generated
preview text uses stdout; CLI tracing uses stderr. Automatic generator selection
checks tool candidates without proving they execute successfully; choose `native`
explicitly to use the native path.

### CMake options

| Option | Description |
|--------|-------------|
| `--cmake-build-dir <DIR>` | CMake build directory with file-api data |
| `--cmake-config <NAME>` | Configuration (Debug/Release) |
| `--cmake-file-api-only` | Require file-api (fail if unavailable) |

File API replies must belong to the selected source root. Normal validation
refreshes replies before capture; preview and `--unsafe-mode` use existing replies.
Use `--cmake-config` to select a named codemodel configuration; otherwise the
adapter selects the first available configuration. File API input does not import
test registrations or prove semantic equivalence.

### Generator options

| Option | Description |
|--------|-------------|
| `--build-generator <TYPE>` | Generator: `auto`, `native`, or `bazelle` |
| `--bazelle-root <DIR>` | Path to bazelle workspace |
| `--bazelle-bin <PATH>` | Path to bazelle binary |

### Examples

**Basic migration:**
```bash
rebaze migrate .
```

**Preview changes:**
```bash
rebaze migrate . --dry-run
```

**With custom config:**
```bash
rebaze migrate . --config custom.toml
```

**CMake with explicitly required File API evidence:**
```bash
mkdir -p build/.cmake/api/v1/query
touch build/.cmake/api/v1/query/codemodel-v2
cmake -S . -B build
rebaze migrate . --build-generator native --cmake-build-dir build --cmake-file-api-only
```

**Specific CMake configuration:**
```bash
rebaze migrate . --cmake-build-dir build --cmake-config Release
```

**Force native generator:**
```bash
rebaze migrate . --build-generator native
```

## `rebaze validate`

Verify generated Bazel files build successfully.

```bash
rebaze validate /path/to/project
```

| Option | Description |
|--------|-------------|
| `--unsafe-mode` | Skip bazel build validation |

Runs `bazel build //...` and verifies Bazel 9.x is being used.

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Success |
| `1` | Error |

## Environment variables

| Variable | Description |
|----------|-------------|
| `RUST_LOG` | Log level: `debug`, `info`, `warn`, `error` |

**Debug logging:**
```bash
RUST_LOG=debug rebaze migrate .
```

<Aside type="tip">
Use `RUST_LOG=debug` to see exactly what rebaze is parsing and how it maps dependencies.
</Aside>
