Create a `rebaze.toml` in your project root to configure native CMake generation.
Use `--build-generator native` for this path. Gradle Java and bazelle currently
accept only default configuration; explicit overrides are rejected rather than
ignored. Unknown fields and mixed flat/nested formats are errors. An absent file
selects defaults; malformed or unreadable files fail visibly.

Use either flat sections such as `[build]`, or place every section under `[bazel]`
(such as `[bazel.build]`). Do not mix them in one file.
Omitted mapping fields retain built-in defaults. Supplied maps/lists replace their
field, except source catalog entries merge into the built-in catalog by key; each
supplied source entry replaces that complete entry.

## Common recipes

Copy-paste these for common scenarios:

### Minimal config

```toml
[versions]
rules_cc = "0.2.27"
```

### Map a custom library

```toml
[mappings.system_libraries]
mylib = "@mylib"
```

### Source archives

```toml
[strategy]
default = "source"

[mappings.known_packages.zlib]
version = "1.3.1"
url = "https://github.com/madler/zlib/releases/download/v1.3.1/zlib-1.3.1.tar.gz"
sha256 = "9a93b2b7dfdac77ceba5a558a580e74667dd6fede4585b91eefb60f03b72df23"
strip_prefix = "zlib-1.3.1"
build_system = "cmake"
out_static_libs = ["libz.a"]
```

### Mix providers

```toml
[strategy]
default = "system"

[strategy.overrides]
zlib = "source"
```

### CMake package mapping

```toml
[mappings.packages.OpenSSL]
target_pattern = "@openssl//:{component}"

[mappings.packages.OpenSSL.components]
SSL = "@openssl//:ssl"
Crypto = "@openssl//:crypto"
```

## Full reference

### `[versions]`

Pin Bazel dependency versions:

```toml
[versions]
rules_cc = "0.2.27"
platforms = "0.0.11"
rules_foreign_cc = "0.14.0"
googletest = "1.15.2"
google_benchmark = "1.9.1"
```

### `[strategy]`

Select `system`, `source`, or `bcr` for managed pkg-config dependencies:

```toml
[strategy]
default = "system"
bcr_fallback = "system" # system or source, for unresolved/skipped BCR packages

[strategy.overrides]
zlib = "source"

[strategy.bcr.version_pins]
zlib = "1.3.1.bcr.5"
```

A normalized CMake prefix override wins over package/catalog overrides, then the
default applies. `strategy.bcr.module_overrides` maps original module names to
replacement names; `strategy.bcr.skip_packages` selects fallback for listed
packages. Pins apply after module overrides. Replacements must provide the same
package/target layout. Unsupported strategy spellings fail planning, including
unused overrides. See [Dependency Strategies](/rebaze/concepts/dependency-strategies/)
for constraints, scope, and system compiler-flag limits.

### `[mappings]`

These external mapping rules apply after exact local targets and prepared managed
links are resolved. Required unresolved links fail preparation. A label mapping
does not itself make the destination repository available.

#### System libraries

Map `-l` flags to Bazel targets:

```toml
[mappings.system_libraries]
z = "@zlib"
ssl = "@openssl//:ssl"
crypto = "@openssl//:crypto"
gtest = "@googletest//:gtest"
```

#### Plain libraries

Map library names without `-l` prefix:

```toml
[mappings.plain_libraries]
gtest = "@googletest//:gtest"
boost = "@boost"
```

#### CMake packages

Map imported target namespaces/components:

```toml
[mappings.packages.Boost]
target_pattern = "@boost//:{component}"

[mappings.packages.Boost.components]
filesystem = "@boost//:filesystem"
system = "@boost//:system"
```

#### Implicit system libraries

Libraries to ignore (linked by default):

```toml
[mappings]
implicit_system_libs = ["pthread", "c", "m", "dl", "rt"]
```

#### Ignored libraries

External link items to omit deliberately. Use an ignore only when no generated
edge is needed; it does not override exact local or prepared managed identities:

```toml
[mappings]
ignored_libraries = ["fmt", "spdlog", "Threads::Threads"]
```

#### Transitive dependencies

Declare deps that pull in other deps:

```toml
[mappings.transitive_deps]
glib = ["pcre2", "libffi", "zlib"]
curl = ["zlib", "openssl"]
```

#### System linkopts

Reserved legacy data: managed system wrappers use the explicit pkg-config
observation. Non-default `mappings.system_linkopts` overrides are rejected;
leave this field omitted.

### `[mappings.known_packages]`

Define active source builds. Entries require complete archive metadata and library
outputs; see [Build from Source](/rebaze/guides/source-builds/) for options,
transitives, and validation:

```toml
[mappings.known_packages.zlib]
version = "1.3.1"
url = "https://github.com/madler/zlib/releases/download/v1.3.1/zlib-1.3.1.tar.gz"
sha256 = "9a93b2b7dfdac77ceba5a558a580e74667dd6fede4585b91eefb60f03b72df23"
strip_prefix = "zlib-1.3.1"
build_system = "cmake"  # cmake | meson | autotools
pkg_config_packages = ["zlib"] # Used for system overrides of source transitives
build_options = ["-DBUILD_SHARED_LIBS=OFF"]
out_static_libs = ["libz.a"]
```

### `[build]`

Configure the root BUILD file and language defaults:

```toml
[build]
default_visibility = "//visibility:public"
default_cxx_standard = "17"
default_c_standard = "11"
module_version = "0.1.0"
```

`default_visibility` supports `//visibility:public` and `//visibility:private`
for production/test targets in the root BUILD file. Third-party wrapper visibility
is separate. Other visibility policies need further implementation.

Language defaults apply when that language is present and the source has no
detected standard. Supported C++ values are `98`, `03`, `11`, `14`, `17`, `20`,
`23`, and `26`; C values are `89`, `90`, `99`, `11`, `17`, `18`, and `23`.
Supported source-detected standards take precedence. C flags use Bazel's
[C-only options](https://bazel.build/versions/9.0.0/docs/user-manual#flag--conlyopt)
so they also work in mixed C/C++ projects without being applied to C++ compilation.
Compiler support for a selected standard remains a separate compatibility check.

`build.header_patterns` is reserved: non-default overrides are rejected. Leave
it omitted until configurable header ownership/globs are implemented.

#### Custom rules

Use your own rule implementations:

```toml
[build.rules]
library_rule = "my_cc_library"
binary_rule = "my_cc_binary"
test_rule = "my_cc_test"

[[build.rules.extra_loads]]
bzl = "@company//build:rules.bzl"
items = ["my_cc_library", "my_cc_binary"]
```

### `[filters]`

Native generation retains its built-in filtering profile. Custom pattern semantics
are not implemented: non-default overrides of `excluded_source_extensions`,
`excluded_define_patterns`, `excluded_copt_patterns`, or
`excluded_include_patterns` fail preparation. Leave `[filters]` omitted. This
avoids silently accepting settings that do not affect generation.

## Complete example

<Aside type="tip">
  See [rebaze.example.toml](https://github.com/albertocavalcante/rebaze/blob/main/rebaze.example.toml) for a valid configuration template. Explicit external mappings still require
  compatible module declarations in the generated project.
</Aside>

```toml
# rebaze.toml - Complete example

[versions]
rules_cc = "0.2.27"
rules_foreign_cc = "0.14.0"
googletest = "1.15.2"

[strategy]
default = "system"

[strategy.overrides]
zlib = "source"

[mappings.system_libraries]
z = "@zlib"
ssl = "@openssl//:ssl"
crypto = "@openssl//:crypto"

[mappings]
implicit_system_libs = ["pthread", "c", "m", "dl", "rt"]
ignored_libraries = ["Threads::Threads"]

[mappings.known_packages.zlib]
version = "1.3.1"
url = "https://github.com/madler/zlib/releases/download/v1.3.1/zlib-1.3.1.tar.gz"
sha256 = "9a93b2b7dfdac77ceba5a558a580e74667dd6fede4585b91eefb60f03b72df23"
strip_prefix = "zlib-1.3.1"
build_system = "cmake"
out_static_libs = ["libz.a"]

[build]
default_visibility = "//visibility:public"
default_cxx_standard = "17"

```
